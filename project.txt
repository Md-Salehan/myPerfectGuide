

## Frontend architecture summary

From the current workspace state and the live app entry points in package.json, main.tsx, App.tsx, AppRoutes.tsx, and baseApi.ts, this is a Vite + React 19 + TypeScript frontend with:

- Redux Toolkit + React Redux for local state
- RTK Query for API layer scaffolding
- React Router for page navigation
- Tailwind-based styling with shared CSS utilities
- Course catalog, checkout, and product-detail flows built as routed pages
- No Firebase or auth provider is configured in the current source

## 2) File-by-file documentation

### Root app entry and global shell

- package.json — Project manifest for the Vite frontend; defines React, Redux, RTK Query, router, Tailwind, and build scripts. It is the source of the app’s dependency graph and standard dev workflow.
- main.tsx — Bootstrap file that mounts the app into the root DOM node and imports the global stylesheet.
- App.tsx — Top-level app wrapper that provides Redux store and BrowserRouter context, then renders the route tree.
- index.css — Global styling entry; contains the shared CSS classes used across the platform, including button styles, layout utilities, and common design tokens.
- App.css — App-local stylesheet layer; mostly global visual overrides and page-level CSS hooks for the existing front end.
- .DS_Store — macOS Finder metadata file; not used by the app runtime.

### App state and typed hooks

- store.ts — Redux store configuration with RTK Query reducer and two app slices: ui and callback. It exports typed RootState and AppDispatch for the rest of the app.
- hooks.ts — Typed Redux wrappers for useDispatch and useSelector, used to maintain TypeScript-safe interaction with the store.

### Routing and layout

- paths.ts — Centralized route constants for home, about, contact, checkout, course pages, and all-courses.
- AppRoutes.tsx —Route tree for the app; it wraps all normal page routes inside the main layout and exposes checkout as a standalone route.
- MainLayout.tsx — Shared page shell containing Header, Footer, WhatsAppButton, and the global callback modal.
- Header.tsx — Responsive navigation header with desktop/mobile menu logic, app branding, CTA buttons, and callback modal dispatch.
- Footer.tsx — Footer shell for navigation; likely renders grouped links and legal/marketing footer columns.
- WhatsAppButton.tsx — Floating WhatsApp CTA used as a global conversion trigger.
- RequestCallbackModal.tsx — Modal wrapper that binds the generic modal primitive to the Redux-driven callback state.
- RequestCallback.tsx — Reusable callback form with validation, success state, slot selection, and async submit handling.
- callbackSlice.ts — Redux slice controlling whether the callback modal is open or closed.
- uiSlice.ts — Placeholder global UI slice for future shared UI state, with mobile-menu toggles defined but not currently used by the app.

### Shared types and constants

- common.ts — Shared cross-cutting interfaces for navigation and footer links.
- course.ts — Canonical course/product type definitions including plan structures, pricing metadata, promo thumbnails, and course metadata.
- faq.ts — FAQ item and grouping types used by product-detail FAQ sections.
- review.ts — Minimal review model for testimonial content.
- navigation.ts — Header navigation arrays for desktop and mobile menus.
- api.ts — API base constants used by the app’s service layer.
- footerLinks.ts — Footer link definitions for site navigation.
- site.ts — Site metadata and shared values such as brand config.

### Course catalog and data

- courses.ts — Main course catalogue that contains the EdTech product data for taxation, digital marketing, and other offerings, including pricing, plans, ratings, summaries, and promo thumbnails.
- formatPrice.ts — Small utility to format currencies/price strings consistently for display in UI.

### Reusable UI building blocks

- Button.tsx — Generic button/link component that renders either a button or anchor element using consistent CSS classes.
- Modal.tsx — Generic accessible modal primitive with backdrop handling, focus trap, escape-to-close, and body scroll lock.
- OtpInput.tsx — OTP entry component used in checkout verification flows.
- Badge.tsx — Small labeled badge component for status/feature tags.
- Banner.tsx — Shared banner component for promotional or informational content.
- CourseCard.tsx — Reusable course-card component used in course list pages and catalog blocks.
- FooterBanner.tsx — Footer promo banner block for marketing or CTA content.
- Logo.tsx — Brand logo component for header/footer branding.
- Tag.tsx — Small tag/chip element for course metadata or category labels.
- SidebarEnrollCard.tsx — Product sidebar card used on detailed course pages; shows pricing, plan selection, and enrollment CTAs.
- index.ts — Section barrel export for product-detail reusable sections.
- HeroSection.tsx — Product hero section used in marketing/detail pages.
- CourseHighlights.tsx — Generic course highlights panel for product pages.
- ToolsYouMaster.tsx — “Tools you master” learning section for product educational pages.

### API layer and backend integration

- baseApi.ts — Shared RTK Query base API instance using VITE_API_BASE_URL or /api. It configures the base URL and leaves the endpoint definitions empty until a real API is wired in.
- checkoutApi.ts — Concrete checkout API endpoints for phone/email OTP, coupon validation, GST validation, and order creation. These are typed and exposed as generated RTK Query hooks.
- mockes — Present as a file-like artifact in the current workspace; not an active directory and not part of the runtime shape.
- checkoutMocks.ts — Mock data and response shims used to simulate OTP/coupon/GST/order flows during front-end development.

## Overall codebase assessment

This frontend is structured as a route-driven education platform with:

- layered page composition for home, catalog, checkout, and course detail pages
- reusable shared UI primitives
- a centralized catalog model in courses.ts
- Redux slices for modal state and future UI state
- RTK Query scaffolding for checkout and API integration, but no live backend implementation is connected yet
- no Firebase auth or DB integration detected in the current app source
